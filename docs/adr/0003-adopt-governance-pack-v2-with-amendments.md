# ADR-0003: Adopt governance pack v2 with amendments

- Status: accepted
- Accepted by: Avinash (architecture owner), 2026-10-04; coordinator decision recorded by the coding agent from Avinash's instruction of 2026-10-04 (SIN-B0.1-002); confirm with an architecture-owner review comment on the B0 PR
- Date: 2026-10-03
- Owners: platform lead
- Supersedes: the B0 scaffold's root docs where they differ from pack v2

## Context
`Sindri_Repository_Governance_and_Phase_Execution_Pack_v2` adds a phase-execution layer (P1–P6
subphases, gates, a bootstrap gate B0, a task board, the anti-skeleton rule, phase-scoped task IDs)
on top of the repository constitution. A review found defects that would mislead agents:
1. `scripts/new_task.py` and `scripts/show_ready_tasks.py` were saved as one line with literal `\n`;
   Python read each whole file as a comment, so both exited 0 and did nothing.
2. B0 was referenced but never defined.
3. `ARCHITECTURE_GUARDRAILS.md` listed two authority modes, dropping the master's
   `correct_by_construction`, which Task Forge T3 generator families depend on.
4. The 15-principle rewrite no longer stated two master principles: measured label precision, and
   independence through information hiding.
5. The verification-forge clean-room rule was softened to "should not copy candidate internals",
   while the master (§11.2) says no oracle author sees golden or candidate RTL.
6. The active phase was recorded in three places (`CURRENT_PHASE.md`, `PROJECT_STATE.md`,
   `implementation/current.yaml`), against the pack's own no-duplicate-source-of-truth rule.
7. CI notes named `pyright`, while ADR-0001 chose `mypy`.

## Decision
Adopt pack v2 as the governance base (`governance-v1.1`) with these amendments:
- Rewrite the two broken scripts; merge the bootstrap script so it prints the phase state, active
  phase file, task packet, handoff, local AGENTS chain, ADRs and git state that AGENT_KICKOFF requires.
- Define B0 (`docs/implementation/phases/B0_BOOTSTRAP.md`) with a gate evidence packet.
- Restore `CORRECT_BY_CONSTRUCTION`; add principles 16–17; restore the strict clean-room wording.
- `implementation/current.yaml` is the only authoritative phase/gate state and
  `implementation/task_board.yaml` the only task status list; Markdown points to them.
  `tests/unit/test_governance.py` enforces consistency.
- Task IDs: `SIN-P<phase>.<subphase>-<nnn>`, plus `SIN-B0.<n>-<nnn>` for bootstrap work.
- Apply the anti-skeleton rule retroactively: delete empty future packages and placeholder folders.
  Packages appear when a task needs them; their import rules are fixed in advance in the guardrails
  and the boundary test (which uses a fixed package list so rules cannot be vacuous).
- Static typing stays `mypy --strict`.
- The master architecture becomes text-native at `docs/architecture/MASTER_ARCHITECTURE.md`,
  generated by `scripts/docx_to_md.py`; the .docx in `docs/reference/` stays the canonical original.

## Alternatives considered
### Adopt pack v2 verbatim
Fastest, but ships no-op scripts and an authority model inconsistent with the master architecture.
### Keep the earlier scaffold and cherry-pick v2 ideas
Loses the phase/gate discipline that v2 introduces, which is its main value.

## Consequences
The earlier TASK-0001 is replaced by `SIN-P1.1-001`, narrowed to P1.1 (the FIFO contract moves to
P1.6, tool pinning to P1.4). Any future change to phase or gate semantics follows
`docs/implementation/IMPLEMENTATION_PLAN.md` change control.
