## JSON Schema fidelity (G-JS: structural projection; documented, not pinned by tests)
The Pydantic models are the only validation authority. The exported schemas currently **do not express**:
- typed-ID and `ContentId` patterns (they are plain `string`);
- the `schema_version` pin to 1 (plain `integer`);
- non-blank text, the UTC-second timestamp format, and summary/claim length limits;
- strict scalar semantics (JSON Schema `integer` admits `1.0`; the models reject it, and every float, at any depth);
- uniqueness constraints inside tuples;
- every model-level or cross-field validator: status matrix, `execution_key` and `source_hash` recomputation, version-chain shape, edge tables, budgets;
- all cross-record invariants (009).

Tests deliberately do not assert that these gaps remain, so later enrichment (G-JS option b) is allowed without breaking anything.

- **G-B (hard pre-P1.2-write condition):** hybrid ID policy. Human-authored or domain-local IDs stay readable; system-minted concurrent IDs must be coordination-free and collision-resistant. A central allocator is not the default. **No ID pattern was changed by this gate.**
- **G-F:** the generic canonical encoder is unchanged; record and hash inputs are float-free (A5).

- **G-S / G-U:** strict byte ingest (duplicate key / NaN / Inf / malformed), explicit integer storage range, global uniqueness and head authority, and closed-bundle assembly remain hard P1.2 entry requirements.
